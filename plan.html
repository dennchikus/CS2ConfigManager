CS2 Config Manager

План разработки · портативная утилита для переноса конфигов CS2

📁 Структура проекта

CS2ConfigManager/
├── main.py                      # точка входа
├── pyproject.toml
├── uv.lock
├── .gitignore
├── README.md
├── PLAN.html
├── app/
│   ├── __init__.py
│   ├── ui/
│   │   ├── __init__.py
│   │   ├── mainwindow.ui        # Qt Designer
│   │   └── main_window.py       # класс окна + сигналы
│   ├── core/
│   │   ├── __init__.py
│   │   ├── paths.py             # пути: ресурсы vs данные
│   │   ├── steam.py             # поиск userdata
│   │   ├── configs.py           # копирование + бэкап
│   │   └── categories.py        # графика / клавиши
│   └── resources/
│       └── icons/
├── storage/                     # конфиги пользователя (рядом с .exe)
└── tests/
Почему так: ui и core разделены — интерфейс меняется часто, логика редко. storage/ в корне, а не внутри app/, потому что при сборке в .exe именно эта папка остаётся снаружи, рядом с исполняемым файлом — это и делает программу портативной.

🗺️ Этапы

1
Подготовка среды
  • Python 3.11+, uv установлен
  • uv init --bare, uv add PyQt6
  • Структура папок из блока выше
Без этого дальше не двинуться. Всё должно ставиться через uv, не через pip руками.
2
Qt Designer + первый запуск окна
  • Нарисовать mainwindow.ui в Designer
  • Виджеты: 2× QListWidget, чекбоксы, 3 QPushButton
  • Осмысленные objectName: accountsList, configsList, checkboxGraphics, btnFind...
  • В main_window.py — загрузка через uic.loadUi()
  • main.py запускает QApplication + MainWindow
Грузить .ui в рантайме, а не конвертировать в .py — гибче, можно менять интерфейс мышкой без пересборки.
3
paths.py — единая точка путей
  • resource_path() — для .ui, иконок (внутри .exe)
  • data_path() — для storage/ (рядом с .exe)
  • Развилка: getattr(sys, 'frozen', False) — определяет, запущено ли как .exe
Это скелет портативности. Если сделать поздно — придётся переписывать все пути в проекте.
4
steam.py — поиск userdata
  • Найти папку Steam (обычно C:\Program Files (x86)\Steam)
  • Внутри — userdata\<SteamID>\730\local\cfg\
  • Вернуть список: SteamID + путь + (опционально) имя аккаунта
  • Обработать случай: Steam на другом диске / портативный
В CS2 настройки лежат именно в userdata, а не в steamapps. И ключевые файлы — config.cfg и cs2_video.txt.
5
categories.py — какие файлы = графика
  • Словарь: {"graphics": ["cs2_video.txt", ...], "keys": ["config.cfg", ...]}
  • Категория = список имён файлов
  • UI при «применить» собирает выбранные категории в плоский список
Данные в одном месте — легко добавить новую категорию, не трогая логику копирования.
6
configs.py — копирование + бэкап
  • save_to_storage(account_path, files) — из аккаунта в storage/
  • apply_to_account(account_path, files) — из storage/ в аккаунт
  • Перед apply — бэкап текущих файлов в storage/_backup/<timestamp>/
Без бэкапа ты однажды затрёшь чужой конфиг и будешь виноват. Бэкап — не опция, а обязательная часть.
7
Связываем UI и логику
  • btnFind.clicked → steam.find_accounts() → заполнить accountsList
  • Выбор аккаунта → показать конфиги в configsList
  • Чекбоксы → при apply фильтруют, какие файлы копировать
  • Кнопки «Сохранить» / «Применить» → вызов из configs.py
  • Обратная связь: QMessageBox при ошибках и успехе
Сигналы подключай в main_window.py, не в main.py. main.py — только запуск.
8
Тест «туда-обратно»
  • Сохранить конфиг из аккаунта А в storage
  • Применить на аккаунт Б
  • Проверить в игре / сравнить файлы вручную
  • Убедиться, что бэкап создался
Не собирай .exe, пока это не работает стабильно на 2+ аккаунтах. Иначе будешь ловить баги вслепую.
9
(Опционально) украшательства
  • Иконка приложения
  • Отображение имени аккаунта вместо SteamID
  • «Открыть папку storage» кнопкой
  • Запоминание последнего выбранного аккаунта
10
Сборка в .exe для флешки
  • uv add --dev pyinstaller
  • Флаг --add-data для mainwindow.ui и иконок
  • Флаг --onefile для одного файла (или --onedir — быстрее старт)
  • Проверить: storage/ создаётся рядом с .exe, не внутри
После сборки sys.argv[0] в paths.py не работает — надо sys.executable. Мы это заложили в шаг 3, так что переписывать не придётся.

🎯 С чего начать прямо сейчас

  • 1. Проверить uv run python -c "import PyQt6; print('ok')"
  • 2. Создать структуру папок и пустые __init__.py
  • 3. Открыть Qt Designer, нарисовать mainwindow.ui, сохранить в app/ui/
  • 4. Написать main.py (5–10 строк: приложение + окно) и запустить
Цель первого дня — увидеть пустое окно из Designer. Всё остальное приложится.
